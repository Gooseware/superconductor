Architecting a Privacy-First, Air-Gapped Codebase Intelligence PipelineThe rapid onboarding, analysis, and comprehension of brownfield software environments require a sophisticated amalgamation of reverse engineering, static analysis, and historical metadata extraction. When these environments represent highly sensitive, proprietary, or classified infrastructure, the intelligence gathering pipeline must operate under a strict zero-trust, privacy-first paradigm. This mandates the utilization of tools that execute entirely locally, offline, and within air-gapped perimeters, ensuring that proprietary source code and intellectual property never traverse an external network.The objective is to aggregate disparate, language-agnostic streams of machine-readable data—such as abstract syntax trees (AST), temporal coupling matrices, and vulnerability manifests—into a structured format tailored for an Artificial Intelligence (AI) review panel. In this architecture, the AI serves not as the primary code scanner, but as the master synthesizer of deterministic, locally generated telemetry. This methodology prevents the hallucination of structural elements by grounding the AI in factual, statically derived JSON inputs.1. Architecture & UML Generation (Reverse Engineering)The automated generation of structural diagrams from raw source code transforms opaque object-oriented or functional hierarchies into legible architectural blueprints. For air-gapped environments, the tooling must parse code locally and output standard declarative markup without relying on cloud-based rendering engines or telemetry-gathering SaaS platforms.Modern architectural reverse engineering relies increasingly on Abstract Syntax Trees (AST) rather than lexical regular expressions. Tools leveraging the incremental parsing libraries represent the gold standard for this task, as they understand the semantic relationships between language nodes without requiring a fully configured build environment. The outputs from these tools are typically domain-specific languages (DSLs) like Mermaid, PlantUML, or Graphviz DOT, which can be programmatically rendered or fed directly into an LLM context window to provide the AI with spatial awareness of the codebase.The ecosystem features several potent tools capable of extracting these diagrams. Auto-UML, built on top of tree-sitter, is language-agnostic and generates Mermaid class diagrams at high velocity without requiring runtime dependencies. Similarly, PlantUML has served as the enterprise standard for over a decade, though it demands a local Java Runtime Environment and utilizes a more verbose syntax optimized for precise UML 2.5 compliance. Dependency Graph & Coupling AnalysisMapping inter-module dependencies is a foundational requirement for identifying architectural decay, circular dependencies, and monolithic coupling within legacy systems. While reverse engineering constructs visual diagrams, dependency analysis generates directed graphs representing the import and linkage structures between discrete software components. The most robust tools operate at the AST or bytecode level rather than relying on rudimentary regex string matching, providing highly accurate structural data for the AI synthesizer.Language-Specific Dependency AnalyzersIn the JavaScript and TypeScript ecosystems, dependency-cruiser acts as a powerful validator and visualizer. It walks through files to validate against custom rules (such as blocking circular dependencies) and emits JSON or GraphViz DOT formats. The Python ecosystem features tools like pipdeptree, which reads the environment to display installed package trees but is inherently tied to the local virtual environment's state, rather than the source code's intent. Conversely, pydeps extracts imports by examining Python bytecode, while deptry performs static AST walks to find unused or missing dependencies, comparing imports against pyproject.toml configurations.For compiled languages, Java utilizes the native jdeps command-line tool introduced in JDK 8. It analyzes the static dependencies of .class files or entire JARs at both the package and class level. In the Rust domain, cargo-modules provides internal module structure visualizations, while cargo-deps builds crate-level dependency graphs; both rely heavily on the local Cargo environment. Code Metrics & ComplexityQuantifying technical debt without relying on network-bound SaaS solutions requires the calculation of cyclomatic complexity (the number of independent, linear paths through a function's control flow), cognitive complexity (a measure of human readability), and aggregate lines of code (LOC). When these metrics are structured into JSON, the orchestration pipeline can programmatically isolate "hotspot" files that warrant prioritized AI review.To evaluate complexity, lizard stands out as an extensible analyzer supporting over 15 programming languages, including C/C++, Java, C#, and Python. Crucially, lizard operates without requiring header files, includes, or complex build environments, making it ideal for immediate execution on raw, unstructured brownfield code. For raw inventory and LOC counting, tools like scc (SLOC, CLOC, and Code) and tokei utilize heavily optimized Go and Rust implementations respectively to parse millions of lines of code in seconds, correctly handling nested comments and multi-language files. Git History Intelligence (Fully Local)While static code analysis reveals the current state of a software system, analyzing Version Control System (VCS) logs uncovers the behavioral evolution of the engineering organization. Git history intelligence identifies deep architectural issues that static parsers cannot detect: temporal coupling (unrelated files that frequently change together in the same commit), knowledge silos (high "bus factor" areas maintained by a single developer), and codebase churn hotspots.Adam Tornhill's code-maat is a foundational tool for forensic VCS analysis, taking raw git log output and processing it locally to compute temporal coupling and entity ownership matrices. Another powerful utility, git-of-theseus, analyzes repository survival rates to determine the "half-life" of code, helping teams understand what percentage of legacy code remains intact over time. For enterprise-scale repositories, hercules utilizes Directed Acyclic Graphs (DAGs) in Go to process massive commit histories orders of magnitude faster than Python-based alternatives, outputting rich burndown and structural statistics. Symbol Extraction & Entry Point DiscoveryBefore an AI can assess a legacy codebase, it must comprehend the public interface and exposed entry points of the application. The intelligence pipeline must extract function signatures, class hierarchies, and APIs without executing the code or relying on an external network connection.The traditional standard, universal-ctags, parses dozens of languages using lexical regular expressions to generate an index of language objects. By invoking it with JSON formatting (--output-format=json), it generates machine-readable tag files that list every variable, function, and class alongside its line number and scope. However, because universal-ctags relies on lexical analysis, it can stumble on highly dynamic, metaprogramming-heavy, or macro-driven legacy codebases.A more modern and robust alternative is the deployment of Tree-sitter AST parsers or headless Language Server Protocol (LSP) instances. tree-sitter-analyzer (TSA) relies on ASTs to achieve cross-language correctness, ensuring symbols are correctly mapped to their definitions across 13+ languages. TSA outputs in TOON format, which is specifically optimized for LLM token context windows, dramatically reducing the payload size compared to standard JSON. Security & Vulnerability Surface (Offline SAST)A core tenet of privacy-first analysis is the execution of Static Application Security Testing (SAST) and Software Composition Analysis (SCA) securely within the air-gap perimeter. Many contemporary SAST solutions refuse to operate without phoning home to a SaaS backend for rule updates or license verification. To maintain the zero-trust paradigm, the orchestrator must utilize tools capable of functioning with pre-cached, local vulnerability databases.For SCA, trivy and grype are the industry standards for scanning container images and filesystems for known CVEs. Both tools require an initial online step to download their vulnerability databases (e.g., trivy image --download-db-only --cache-dir ./cache or grype-db -g). Once the database archive is transferred to the air-gapped machine, the tools operate entirely offline, emitting comprehensive JSON or SARIF reports. To prevent the tools from failing during the scan due to stale database checks, specific flags must be utilized: --skip-db-update for Trivy, and setting environment variables GRYPE_DB_AUTO_UPDATE=FALSE and GRYPE_DB_VALIDATE_AGE=FALSE for Grype.For pure SAST, semgrep provides a highly versatile, polyglot scanning engine. While the default semgrep scan --config=auto command attempts to connect to the Semgrep registry, developers can pre-download YAML rule bundles. By invoking semgrep scan --config ./local-rules-dir --json, the tool executes entirely locally. Test Coverage Discovery (Without Running Tests)Determining exact test coverage natively requires compiling the software and executing the test suite with a dynamic coverage profiler (e.g., JaCoCo, Istanbul). In a brownfield scenario, legacy codebases frequently suffer from broken build chains, missing databases, or unresolvable dependencies, making dynamic execution impossible. Therefore, the orchestration pipeline must infer test coverage gaps statically, analyzing the code without execution.Static test gap analysis relies on Import Graph Analysis and Structural Reachability. The orchestration script begins by identifying all exported modules and classes in the primary source directory using tools like tree-sitter-analyzer. Subsequently, it parses the tests/ or spec/ directories to map all import statements. If a source file or class is never explicitly imported or invoked by any file within the testing directory, it is mathematically verified to possess 0% direct unit test coverage.Furthermore, static call graph analyzers (such as go-callvis for Golang or dependency-cruiser for JavaScript) can trace the reachability of internal functions. If deep logical branches within a module are entirely disconnected from the invocation paths originating in the test files, those specific code paths represent critical coverage gaps. By layering this static coverage inference over the Git Churn data, the orchestrator identifies the most dangerous legacy components: files that experience extreme modification volatility but remain completely unreferenced by the test architecture.8. Documentation & API Surface ExtractionUnderstanding the exported boundaries of a legacy system requires tools that can identify public interfaces, flag undocumented functions, and synthesize API specifications without manual human intervention or external API lookups.The tree-sitter-analyzer (TSA) excels in this domain. Through its robust AST querying engine, it can execute specific curations (termed "Skills") to extract public APIs, class hierarchies, and inline documentation (e.g., JSDoc, TSDoc, docstrings) across multiple languages. Because it outputs in TOON format—a tabular JSON variant designed to cut bulk payload sizes by half—it is uniquely optimized for feeding dense documentation surfaces into constrained LLM context windows.For language-specific deep extraction, tools like cargo-public-api for Rust diff and list the public API of library crates, detecting semver violations and exposing undocumented structs directly from the local environment. Additionally, the orchestration pipeline can utilize custom local semgrep rules designed explicitly to flag any class or function decorated with a public modifier that lacks a corresponding documentation block, instantly quantifying the documentation deficit of the brownfield codebase.9. Orchestration & Meta-Tools (Self-Hostable)Managing a diverse array of CLI tools efficiently requires a local orchestration engine that standardizes configuration, executes tools sequentially, and aggregates disparate outputs without transmitting proprietary code to a SaaS dashboard.Trunk serves as a powerful universal linter and formatter. Operating on a configuration-as-code paradigm via a .trunk/trunk.yaml file, it downloads the required binaries and caches them locally in ~/.cache/trunk. Once the environment is initialized, trunk check executes all configured linters entirely offline, ensuring deterministic, hermetic analysis across the development team.Similarly, Reviewdog acts as a lightweight Go binary that filters the output of any local linter based on git diffs. Designed to consume standard output from pipes (e.g., eslint -f rdjson . | reviewdog -f=rdjson -reporter=local), it operates completely offline and outputs results in a unified Reviewdog Diagnostic Format (RDFormat JSON).For teams requiring an exhaustive suite of tools out of the box, MegaLinter encapsulates over 100 linters within a massive, self-contained Docker image.
