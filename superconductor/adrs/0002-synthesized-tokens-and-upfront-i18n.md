# 2. Automated Token Synthesis & Upfront Localization (i18n / RTL)

Date: 2026-10-01  
Status: Accepted  

## Context
During visual wireframing and interactive in-DOM proposal drafting, two critical risks threaten UI scalability:
1. **Design Token Chaos**: Drafting ad-hoc styles in the browser can inject raw hex values (`#3b82f6`), magic pixel dimensions (`margin: 14px`), and arbitrary CSS literals into components, eroding visual consistency.
2. **Monolingual Hardcoding**: UI components written with hardcoded English strings break when exported or translated, requiring expensive retroactive refactoring for internationalization (i18n) and right-to-left (RTL) locales.

## Decision
1. **Mandatory 4-Tier Token Synthesis (`TokenSynthesizer`)**:
   - The visual studio scanner automatically audits target codebases for existing design tokens (Tailwind, CSS Variables, Design OS Astryx).
   - If a project lacks formal design tokens or contains raw hex/magic spacings, the system synthesizes a normalized 4-tier semantic token taxonomy:
     - *Surfaces & Backgrounds* (`--surface-canvas`, `--surface-card`, `--surface-elevated`)
     - *Content & Typography* (`--text-primary`, `--text-muted`, `--text-accent`)
     - *Brand & State* (`--brand-primary`, `--state-success`, `--state-danger`)
     - *Geometry & Spacing* (`--radius-sm`, `--radius-md`, `--space-4`, `--space-8`)
   - All `InDomProposal` drafts generated by the agent must strictly bind to this token taxonomy.
   - When appropriate, the Note-to-Track Assembly Engine outputs a foundational **"Design System & Token Scaffolding Track"** to formalize the tokens in code.
2. **Upfront Localization & Bidirectional Mirroring (`LocaleMirrorHarness`)**:
   - All text and copy proposals drafted by the agent must be structured with localization keys/macros (e.g. `t('header.title')`).
   - The studio preview embeds an interactive **Locale & Direction Switcher** supporting multi-language simulation and bidirectional RTL mirroring (`dir="rtl"`) to verify text expansion (+30% length checks in German/French) and layout flipping (Arabic/Hebrew) before tracks are finalized.

## Consequences
### Positive
- Zero untokenized CSS magic numbers or raw hex values leaking into generated tracks.
- Automated creation of design token foundations for legacy/brownfield projects.
- Immediate visual proofing against text truncation, overflow, and RTL layout bugs.

### Negative
- Requires maintaining a robust text extraction heuristic during AST scanning to distinguish static display text from internal code identifiers.
